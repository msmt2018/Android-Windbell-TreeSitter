# 编辑器集成指南

## 1. 目标

宿主编辑器可以是 Android View、自定义 View、第三方编辑器控件或独立文本组件。TSH 不要求继承特定基类；优先复用标准 Provider，特殊能力再注册扩展。

## 2. 三级适配

1. **自动适配**：识别明确支持的标准 Android 对象和已知 Provider。
2. **通用适配**：通过显式接口、公开能力描述或安全反射探测公开 API。
3. **自定义适配**：仅为未覆盖能力实现 Provider；不要求重写整个编辑器适配层。

自动识别不能等同于对任意 View 猜测其编辑器语义。未知控件必须输出能力诊断。

## 3. 接入流程

1. 创建 TshEngine/上下文。
2. 注册或发现 Editor、Document、TextBuffer、Layout、Renderer 实例。
3. 检查 CapabilitySet。
4. 对缺失能力注册对应 Provider。
5. 加载并验证 .tsh 配置。
6. 创建 EditorSession 并绑定文档。
7. 监听文本变化、选择变化、滚动和生命周期。
8. 启动增量解析/高亮。
9. 将 RenderInstruction 提交给目标 Renderer Provider。
10. 销毁时取消任务、解绑对象、释放资源。

## 4. Provider 原则

Provider 必须声明：
- 支持的能力 ID 与版本。
- 目标对象类型/匹配方式。
- 线程要求。
- 是否支持增量、局部刷新和异步。
- 生命周期与资源所有权。
- 失败时的诊断代码与降级策略。

Provider 不得假设自己拥有宿主编辑器对象。除非契约明确转移所有权，否则只持有弱引用或可失效引用。

## 5. 渲染接入方式

可能的目标机制包括 Canvas/Paint、Span、Decoration、行级绘制钩子、自定义 Renderer。不能把 Spannable 当成唯一方案，也不能对宿主控件直接调用未知私有绘制方法。

## 6. 集成验收

- 标准对象可通过现成 Provider 接入。
- 自定义对象只需实现缺失能力。
- 不支持的能力可被准确报告。
- 编辑、滚动、折叠、主题切换和销毁场景不提交过期结果。
- 真实编辑器显示正确的 .tsh 样式。
